# LocalDrop

Файлы, буфер обмена и звук между компьютерами и телефонами — напрямую по локальной сети, без облака
и регистрации. Windows 10/11, macOS 13+ и Android 11+.

## Возможности

- **Перенос файлов и папок** любого размера: очередь, пауза и продолжение с обеих сторон, докачка
  после обрыва связи, проверка SHA-256 каждого файла, повторные имена не перезаписываются.
  От доверенных устройств файлы принимаются сразу, от остальных сопряжённых — после подтверждения.
- **Буфер обмена**: текст и картинки, автосинхронизация на выбранные устройства, история
  (200 последних записей) с копированием, повторной отправкой и удалением.
- **Звук**: весь звук системы, любое устройство ввода или одно приложение (Windows 10 2004+,
  macOS 13+) на колонки других компьютеров. Opus 96/192 кбит/с или PCM без сжатия,
  синхронное воспроизведение на нескольких устройствах (расхождение меньше 1 мс),
  удалённый выбор выхода и громкости, буфер 10–200 мс.
- **Сопряжение** четырьмя способами: из списка со сверкой 6-значного кода, по IP-адресу,
  вводом кода другого устройства, по QR-коду (веб-камера).
- Трей, системные уведомления, автозапуск, пункт «Отправить через LocalDrop» в Проводнике,
  история, тёмная и светлая темы, русский и английский интерфейс.
- **Android**: всё то же самое с телефона — файлы и папки в обе стороны, буфер обмена, звук с ПК
  в динамик или наушники телефона («Слушать») и звук телефона или микрофон на компьютеры,
  сопряжение по коду, IP и QR (камера телефона). Плюс «Поделиться → LocalDrop» с прямыми целями-
  устройствами, плитка «Отправить буфер» в шторке, виджет, уведомления с кнопками, работа в фоне.

## Запуск из исходников

Нужен Python 3.12+ (проверено на 3.14).

Команды выполняются из корня репозитория.

```
python -m venv .venv
.venv\Scripts\pip install -r desktop\requirements.txt      # macOS: .venv/bin/pip
.venv\Scripts\python desktop\main.py
```

Параметры:

| Параметр | Что делает |
|---|---|
| `--profile NAME` | отдельная папка данных: можно запустить два экземпляра на одном ПК |
| `--port N` | TCP-порт (по умолчанию 53317) |
| `--hidden` | запуск свёрнутым в трей |
| `--send ПУТЬ…` | отправить файлы/папки через уже запущенный LocalDrop |
| `--debug` | подробный журнал |

Два экземпляра на одном компьютере:

```
.venv\Scripts\python desktop\main.py --profile A
.venv\Scripts\python desktop\main.py --profile B --port 53318
```

## Сборка

- Windows: `powershell -ExecutionPolicy Bypass -File desktop\packaging\build_win.ps1` →
  `desktop\dist\LocalDrop\LocalDrop.exe` (папка целиком, около 270 МБ).
- macOS: `sh desktop/packaging/build_mac.sh` → `desktop/dist/LocalDrop.app`. **Не проверялось на Mac.**

### Android

Нужен Android Studio (или JDK 17+ и Android SDK 37). Проект — `android/`.

```
cd android
gradlew.bat :app:assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
gradlew.bat :app:assembleRelease      # app/build/outputs/apk/release/app-release.apk (R8)
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

Release-сборка пока подписывается отладочным ключом: для публикации нужен свой keystore.

## Сеть и брандмауэр

- TCP 53317 — соединения между устройствами; UDP 53317 — поиск устройств (маяк);
  UDP 5353 — mDNS; звук идёт по UDP на случайных портах.
- При первом запуске Windows спросит доступ к сети — разрешите для **частных сетей**.
  Если устройства не видят друг друга, проверьте, что сеть в Windows отмечена как «Частная».
- VPN-туннели при выборе сетевого интерфейса пропускаются; интерфейс можно выбрать вручную
  в «Настройки → Сеть».
- Если устройство в другой подсети, добавьте его по IP («Устройства → Добавить»).
- Android 17+ спрашивает разрешение «Локальная сеть» — без него телефон не увидит компьютеры.
  Телефон работает только через Wi-Fi/Ethernet («Настройки → Только Wi-Fi»), мобильный интернет
  не используется.

## Безопасность

- У каждого устройства свой ключ Ed25519; идентификатор устройства — хеш открытого ключа.
- Соединение: рукопожатие по схеме SIGMA (как TLS 1.3 с закреплёнными ключами) — эфемерный
  X25519, подписи обеих сторон, ключи через HKDF. Всё шифруется AES-256-GCM, звук по UDP — тоже,
  отдельными ключами на каждый сеанс.
- Сверка 6-значного кода и QR-код защищают от подмены при первом сопряжении. Ввод кода другого
  устройства слабее: в течение 60 секунд жизни кода активный злоумышленник в той же сети
  теоретически может вклиниться. Попытки ввода кода ограничены (5 в минуту).
- Несопряжённые устройства могут только предложить сопряжение. Буфер обмена и звук от
  недоверенных устройств не применяются автоматически.

## macOS

Код для macOS написан, но не проверен. Нужно:
- разрешение «Запись экрана» для захвата звука (ScreenCaptureKit);
- разрешения «Микрофон» (захват входа) и «Камера» (сканирование QR);
- «Отправить через LocalDrop» в Finder пока нет (только в Проводнике Windows).

## Android: ограничения системы

- Свой буфер обмена Android даёт читать только приложению на экране: он отправляется кнопкой,
  плиткой в шторке, виджетом, через «Поделиться» или сам при открытии LocalDrop. Принимать буфер
  с компьютеров телефон может и в фоне.
- «Весь звук телефона» захватывается через системный диалог записи экрана (выбирайте «Весь экран»);
  звук приложений, запретивших захват, и звонки не передаются. Для захвата нужно и разрешение
  «Микрофон».
- Чтобы принимать файлы при выключенном экране, разрешите «Работу в фоне» (без оптимизации
  батареи). Некоторые оболочки (MIUI, EMUI и т. п.) всё равно могут выгружать службу — в их
  настройках включите автозапуск для LocalDrop.
- Файлы, выбранные через «Поделиться» или галерею, после перезапуска телефона докачать нельзя
  (система отзывает доступ): такую передачу придётся повторить.

## Данные

- Windows: `%APPDATA%\LocalDrop` (профили — в `profiles\ИМЯ`), macOS: `~/Library/Application Support/LocalDrop`.
- `settings.json` — настройки, `localdrop.sqlite` — устройства, история, буфер, состояние передач,
  `identity.pem` — ключ устройства, `localdrop.log` — журнал («Настройки → Открыть журнал»).
- Android: данные приложения (`settings.json`, `localdrop.sqlite`, ключ устройства вне резервных
  копий); принятые файлы — `Загрузки/LocalDrop` или папка, выбранная в настройках.

## Разработка

```
.venv\Scripts\python -m pytest desktop            # тесты
.venv\Scripts\python desktop\tools\check_i18n.py   # строки без английского перевода
.venv\Scripts\python desktop\tools\subset_icons.py # пересобрать шрифт иконок после новой иконки
.venv\Scripts\python android\tools\subset_icons.py # то же для Android
cd android && gradlew.bat :protocol:test           # протокол Android против настоящего кода десктопа
cd android && gradlew.bat :app:connectedDebugAndroidTest   # Opus через MediaCodec на устройстве
```

Тесты `:protocol` запускают `desktop/tools/interop_peer.py` из `.venv` и проверяют совместимость
с десктопом: рукопожатие, сопряжение всеми способами, передачу файлов с паузой и обрывом, буфер,
аудиопотоки в обе стороны. Без `.venv` эти тесты пропускаются.

Репозиторий: `desktop/` — приложение для Windows и macOS (Python), `android/` — приложение для
Android (Kotlin, Jetpack Compose), `ui/` — интерфейс десктопа.

Структура `android/`: `protocol/` — протокол на чистом Kotlin/JVM (шифрованный транспорт,
устройства, сопряжение, файлы, буфер, звук), повторяет `desktop/localdrop/net|files|clip|audio`;
`app/` — Android: `core/` (ядро, хранилище, обнаружение, файлы, буфер), `audio/` (MediaCodec,
AudioTrack, захват), `service/` (служба, уведомления), `system/` («Поделиться», плитка, виджет),
`ui/` (экраны).

Структура `desktop/`: `localdrop/net` — личность, шифрованный транспорт, обнаружение, сопряжение;
`localdrop/files` — передача файлов; `localdrop/clip` — буфер обмена; `localdrop/audio` — захват,
кодек, синхронный поток; `localdrop/system` — трей, уведомления, автозапуск, меню Проводника;
интерфейс в `ui/` (React + htm без сборки, всё локально).
